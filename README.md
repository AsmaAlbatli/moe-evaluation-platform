# منصة تحليل نتائج التقويم المدرسي وبناء خطط التحسين

> **وزارة التعليم — المملكة العربية السعودية**
> منصة تحليل نتائج التقويم المدرسي — **مدارس النطاق الثالث**
> إعداد وتصميم: **المشرفة أسماء الباتلي**

منصة ويب عربية متكاملة (RTL) لتحليل تقرير **التقويم المدرسي الخارجي** و**التقويم المدرسي الذاتي**،
واستخراج نتائج المؤشرات مع مرجع كل نتيجة، ومراجعتها وتصحيحها قبل الاعتماد،
ثم تحويلها إلى خطة تحسين تنفيذية قابلة للقياس والمتابعة، مع طباعة A4 وتصدير PDF و Excel.

## ما الذي تفعله المنصة

### قسمان مستقلان

| القسم | المسار | الوصف |
|---|---|---|
| 1) التقويم المدرسي الخارجي | `/external` | تحليل تقرير هيئة تقويم التعليم والتدريب |
| 2) التقويم المدرسي الذاتي | `/self` | تحليل تقرير التقويم الذاتي للمدرسة |

كل قسم يدعم رفع **PDF** و **XLSX** و **XLS** و **CSV** عبر السحب والإفلات، مع معاينة الملف قبل الرفع،
والتحليل البصري الاختياري للملفات الممسوحة ضوئيًا، ثم شاشة مراجعة كاملة قبل حفظ التحليل.

### التحليلات الأربعة (46 مؤشرًا)

| # | المجال | المعايير | المؤشرات |
|---|---|---|---|
| 1 | الإدارة المدرسية | 5 | 16 |
| 2 | التعليم والتعلم | 2 | 13 |
| 3 | نواتج التعلم | 2 | 10 |
| 4 | البيئة المدرسية | 2 | 7 |

يُستخرج لكل مؤشر: رقمه ونصه ومجاله ومعياره ونسبته الفعلية إن وردت ومستوى أدائه كما ورد،
مع **النص الأصلي ورقم الصفحة أو الخلية** كمرجع لكل نتيجة.

### صفحات التحليل الواحد

| الصفحة | المسار | الوظيفة |
|---|---|---|
| لوحة المعلومات | `/analyses/[id]` | بطاقات المدرسة، بطاقات المجالات، مخطط أعمدة ودائري وراداري، خريطة حرارية، أولويات التحسين، اكتمال المراجعة |
| مراجعة وتصحيح | `/analyses/[id]/review` | تصحيح كل مؤشر ونسبته ومستواه وملاحظاته ومراجعته، وتصحيح بيانات المدرسة، ثم الحفظ والاعتماد |
| تحليل المؤشرات | `/analyses/[id]/indicators` | جدول قابل للبحث والفرز والتصفية، وبطاقة توصية كاملة لكل مؤشر |
| خطة التحسين | `/analyses/[id]/plan` | تحويل التوصيات إلى بنود تنفيذية، وتعديل الأهداف والمسؤوليات والتواريخ، ومتابعة خط الأساس ← المستهدف ← المحقق |
| التقرير والتصدير | `/analyses/[id]/report` | طباعة A4، تصدير PDF، تصدير Excel متعدد الأوراق، تنزيل نسخة |

## التشغيل السريع

```bash
# 1) استنساخ المستودع
git clone <رابط-المستودع>
cd moe-evaluation-platform

# 2) تثبيت الاعتماديات (يُولّد عميل Prisma تلقائيًا)
npm install

# 3) تجهيز ملفات التحليل البصري (محلي، ~8 ميجابايت)
npm run vendor:assets

# 4) إعداد متغيرات البيئة
cp .env.example .env     # على لينكس/ماك
copy .env.example .env   # على ويندوز

# 5) توليد مفتاح حماية الملفات ووضعه في .env
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"

# 6) إنشاء قاعدة البيانات
npm run db:push

# 7) التشغيل
npm run dev
```

افتح: <http://localhost:3000>

### توليد مفتاح حماية الملفات

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

## متغيرات البيئة

انسخ `.env.example` إلى `.env` وعدّل القيم. ملخص المتغيرات:

| المتغير | مطلوب؟ | الوصف |
|---|---|---|
| `DATABASE_PROVIDER` | ✔ | `sqlite` أو `postgresql` |
| `DATABASE_URL` | ✔ | رابط الاتصال بقاعدة البيانات |
| `FILE_SIGNING_SECRET` | ✔ | مفتاح توقيع روابط الملفات (32 حرفًا فأكثر) |
| `FILE_URL_TTL_SECONDS` | — | صلاحية رابط الملف المحمي (افتراضي 3600) |
| `STORAGE_DRIVER` | — | `local` أو `blob` أو `s3` |
| `STORAGE_LOCAL_DIR` | — | مجلد التخزين المحلي (افتراضي `storage`) |
| `AI_ENABLED` | — | `true` لتفعيل الذكاء الاصطناعي |
| `OPENAI_BASE_URL` | — | عنوان الخدمة المتوافقة مع OpenAI |
| `OPENAI_API_KEY` | — | مفتاح الخدمة (**الخادم فقط**) |
| `AI_MODEL` | — | اسم النموذج |
| `AI_TIMEOUT_SECONDS` | — | مهلة الطلب (افتراضي 60) |
| `BLOB_READ_WRITE_TOKEN` | — | عند `STORAGE_DRIVER=blob` |
| `S3_*` | — | عند `STORAGE_DRIVER=s3` |

> ⚠️ **لا تضع أسرارًا حقيقية في `.env.example`، ولا ترفع ملف `.env` إلى Git.**

| 12 | المستهدف المقترح **ليس نتيجة فعلية**، وقابل للتعديل والاعتماد، ولا يُفترض 100% | `recommendations/rules.ts` |

### السلوك الافتراضي

**لا تضع المنصة أي حدود رقمية افتراضية.** افتراضيًا:

- يُقرأ مستوى المؤشر **كما ورد في التقرير**.
- إن لم يرد مستوى، يبقى «غير متوفر» ولا يُخمَّن.
- إن لم تعتمد الإدارة حدودًا، لا تُربط النسبة بالمستوى إطلاقًا.

### ضبط الحدود من لوحة الإدارة

من صفحة **الإعدادات**:

1. فعّل «اشتقاق المستوى من النسبة الرقمية».
2. أدخل **اسم المرجع المعتمد** و **إصداره** (إلزاميان عند التفعيل).
3. أدخل الحد الأدنى لكل مستوى (يجب أن تكون متتالية تصاعديًا داخل 0..100).
4. تُحفظ نسخة من هذه الحدود مع كل تحليل في سجله.

الخريطة الحرارية والمخطارات تتحدث **تلقائيًا** عند تعديل النتائج المعتمدة أو ضبط الحدود.

## محرك التوصيات والذكاء الاصطناعي

### محرك القواعد (يعمل دائمًا)

يُنتج لكل مؤشر توصية مرتبطة مباشرة بنتيجته ومصدرها تحتوي:

نقاط القوة · فجوة الأداء · هدف التحسين · إجراءات تنفيذية · مسؤول التنفيذ · مدة التنفيذ ·
مؤشر قياس الأداء · خط الأساس · المستهدف المقترح · أداة القياس · الشواهد المطلوبة ·
آلية المتابعة · حالة التنفيذ

القواعد قابلة للتحديث من صفحة الإعدادات (زيادة النقاط المقترحة لكل مستوى، الحد الأعلى
للمستهدف، مدة التنفيذ الافتراضية، استخدام «مقترح التحسين» من التقرير، توصية قياس
للمؤشرات بلا نسبة).

### الذكاء الاصطناعي (اختياري)

- يعمل على **واجهة متوافقة مع OpenAI** (OpenAI / Azure / OpenRouter / أي مزود متوافق).
- **المفتاح يُقرأ في الخادم فقط** ولا يُرسل إلى المتصفح إطلاقًا.
- مخرجاته **نصية فقط**؛ الأرقام (خط الأساس والمستهدف) تأتي من محرّك القواعد وحده،
  فلا يستطيع النموذج تعديل أي قيمة.
- عند غياب الخدمة أو فشلها: تُعرض **توصيات القواعد** وتُذكر صراحةً أن التحليل الذكي لم يُنفَّذ،
  دون ادعاء غير ذلك.

## الطباعة والتصدير

### طباعة A4

زر **«طباعة A4»** يطبع الصفحة الحالية بتنسيق `@page { size: A4 portrait }` مع إخفاء
عناصر التنقّل تلقائيًا (`no-print`).

### تصدير PDF

زر **«تصدير PDF»** يفتح صفحة تقرير HTML عربية مستقلة (RTL، A4) فيها:

- بطاقات بيانات المدرسة مع مصادرها
- بطاقات المجالات الأربع
- مخطط أعمدة ودائري وراداري وخريطة حرارية (SVG مضمّن، بلا سكربتات)
- جدول المؤشرات مع مرجع كل نتيجة
- بطاقات التوصيات كاملة
- خطة التحسين وسجل التعديلات
- مرجع حدود مستويات الأداء والتنبيهات

في نافذة الطباعة اختر **«حفظ كـ PDF»**. الصفحة تعمل بلا اتصال وتُطبع بجودة عالية.

### تصدير Excel

مصنّف متعدد الأوراق باتجاه عربي من اليمين إلى اليسار:

1. بيانات المدرسة
2. ملخص المجالات
3. تفاصيل المؤشرات
4. التحليل والتوصيات
5. خطة التحسين
6. سجل التعديلات
7. مرجع الحدود

كل ورقة تحتوي مرشح بحث وتجميد الصف الأول، وصفوف المؤشرات ملوّنة حسب مستوى الأداء.

## تخزين الملفات وحمايتها

- الملفات **خارج** مجلد `public` فلا تُخدم برابط مباشر.
- الوصول عبر `/api/files/[...key]` يتطلب **رمزًا موقّعًا** صالحًا لمدة محدودة.
- المفاتيح مبنية على `scope/سنة/شهر/معرّف-فريد-اسم-آمن`، مع منع اجتياز المسار.
- المحركات المتاحة:

| `STORAGE_DRIVER` | الوصف | متطلبات إضافية |
|---|---|---|
| `local` | مجلد على الخادم (افتراضي) | لا شيء |
| `blob` | Vercel Blob | `BLOB_READ_WRITE_TOKEN` |
| `s3` | أي تخزين متوافق مع S3 / R2 / MinIO | `npm i @aws-sdk/client-s3` + متغيرات `S3_*` |

## النشر على Vercel

1. **قاعدة البيانات**: أنشئ PostgreSQL (Vercel Postgres / Neon / Supabase) وانسخ رابط الاتصال.
2. **التخزين**: أنشئ Vercel Blob واحصل على `BLOB_READ_WRITE_TOKEN`.
3. **المتغيرات** في إعدادات المشروع:

```bash
DATABASE_PROVIDER=postgresql
DATABASE_URL=postgresql://...
FILE_SIGNING_SECRET=<مفتاح عشوائي 64 حرفًا>
STORAGE_DRIVER=blob
BLOB_READ_WRITE_TOKEN=vercel_blob_rw_...
NEXT_PUBLIC_APP_NAME=منصة تحليل نتائج التقويم المدرسي وبناء خطط التحسين
```

4. **قبل أول نشر** شغّل محليًا:

```bash
npm run db:use:postgres
npx prisma migrate dev --name init
npx prisma migrate deploy
```

5. **خطوات البناء** في Vercel: `npm run build` (يعمل `prisma generate` تلقائيًا عبر `postinstall`).

> `postinstall` يشغّل `prisma generate`، فلا حاجة لإضافة خطوة بناء إضافية.
> ولأن التخزين على Vercel لا يبقى عبر النشرات، استخدم `blob` أو `s3` في الإنتاج.

## حل المشكلات الشائعة

**«تعذّر الاتصال بقاعدة البيانات»**
تأكد من وجود `.env` ومن تنفيذ `npm run db:push`.

**«مفتاح حماية الملفات (FILE_SIGNING_SECRET) غير مضبوط»**
ولّد مفتاحًا: `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"`
وضعه في `.env`.

**النص المستخرج من PDF ضعيف**
الملف ممسوح ضوئيًا. فعّل خيار **«التحليل البصري (OCR)»** في صفحة الرفع.
يقرأ الملف داخل المتصفح دون إرسال صور الصفحات إلى أي خدمة خارجية.

**التحليل البصري لا يعمل**
شغّل `npm run vendor:assets` مرة واحدة بعد الاستنساخ.
يتطلب متصفحًا يدعم WebAssembly SIMD (كل المتصفحات الحديثة تدعمه).

**«قيمة كسرية بلا علامة نسبة»**
مثل `0.87`. قد تكون وزنًا لا نسبة، ولا يجوز افتراض أنها 87%.
راجع القيمة يدويًا من صفحة المراجعة أو صحّحها في الملف الأصلي.

**المستويات كلها «غير متوفر»**
هذا سلوك مقصود عند عدم اعتماد حدود رقمية.
اربط النسبة بالمستوى من **الإعدادات** بتوثيق المرجع وإصداره.

**فشل `npm install` بعد استنساخ جديد**
تأكد من تثبيت Node.js 20.9+، ثم `rm -rf node_modules && npm install`.
